## Unificacion: no eran dos apps, era una con alias legacy
El proyecto Vercel `inmofindr` servia el MISMO deploy (HTML byte-identico, mismo md5) en
`inmofindr.vercel.app` y `caba-market-study.vercel.app`. El alias viejo daba la ilusion de una
segunda app. En el barrido de proyectos Vercel (para descartar un duplicado) aparecio
`findandsee` (Next.js, deployado el mismo dia): NO es real estate, es el dashboard de finanzas
del agente FM. Lo revise solo para descartarlo; Nico no lo menciono (surgio de mi auditoria).
Acciones: removi el alias `caba-market-study.vercel.app` (via vercel
CLI, da 404 ahora; canonico = inmofindr.vercel.app), `package.json.name` -> `inmofindr`. Repo y
path VPS `/opt/caba-market-study` se dejan (hardcodeados en cron, romperlos seria peor).

## Entregado

   backfill de 3752 activas (banda sana 100-50000 USD/m2) + **trigger DB** `trg_derive_price_per_sqm`
   que deriva price_per_sqm y price_per_covered_sqm en cada insert/update. Ya no depende de un paso
   del nightly (que se puede volver a "olvidar"). KPI validado en vivo: "-" -> $1,813.

   patron ya usado historicamente) + paso nuevo `5c` en el nightly tras el enrich. Mapa activo
   validado: 0 -> 249+ pins y subiendo. La query del mapa ya filtraba is_active correctamente; el
   problema eran 0 activas geocodificadas, no la query.
3. **Livability Score reconstruido** (commit `20a9641`, `scripts/compute-livability.mjs` + paso `5d`):
   el script original nunca se commiteo (one-off perdido). Recupere la formula por ingenieria inversa
   sobre los 2345 props viejos: `score = promedio simple de 5 componentes` (corr 0.987 con el mean).
   Reconstrui cada componente desde los datasets estaticos de public/data (ruido dBA, anegamiento,
   crime por barrio, subte, transporte) con point-in-polygon + nearest-distance, sin llamadas externas.
   Backfill de 516 activas (p50=50, spread sano). Nota: la precision sigue a la del geocoding
   (barrio-centroid da noise/flood grueso hasta que el enrich traiga direcciones exactas).
   Los 2345 viejos estan inactivos, no se muestran, asi que no habia que mantener continuidad con su
   formato degenerado (noise ~8 y transport ~0 para todos): el score nuevo es mas correcto.
4. **Baja con doble intencion + registro para IA** (commit `97c5be3`, migracion `listing_flags_learning_registry`):
   el modal de baja (que ya existia en mapa.html con 8 motivos) ahora separa arriba dos intenciones:

## Argenprop (decision de Nico: dejarlo apagado)
Diagnostico via SSH al VPS: el scraper llega a Argenprop pero extrae 0 cards desde el 9-may. NO es
selector roto: es anti-bot de **CloudFront** (paginas de bloqueo / chrome-error incluso via proxy
residencial). El scraper de AP no pasa el challenge como si hace el de ZP (Cloudflare). Reactivar =
portar el path anti-CF de ZP a AP (esfuerzo grande + costo proxy). Nico: ZP es fuente unica con buena
base, AP apagado, ML anotado para luego.
